## Classification rule (dispatch_literal_or_tooldefinition_name)

An id classifies SHIPPED if and only if its exact string literal appears in a dispatch position in live Rust source (outside tool_metadata.rs, outside the mode manifests, outside test code and comments), or it is reached through a prefix dispatch block that names it, or it equals a registered MCP ToolDefinition name. Presence in tool_metadata.rs is never evidence.

**shipped evidence**

- match_arm: the literal is a match arm pattern, alone or inside an alternation ("id" => ..., "a" | "id" => ..., "id" if guard => ...), and the arm body is not a display label and does not say it is unimplemented.
- eq_compare: the literal is compared with == (action == "id" or "id" == action).
- prefix_dispatch: the file gates the id's prefix with `if let Some(V) = X.strip_prefix("P:") { ... }` and, inside that brace block, the name part of the id is compared with V (V == "name") or is an arm of `match V { ... }`.
- mcp_tool_name: the id is exactly equal to a registered ToolDefinition name (name: "..." in crates/tools/src and crates/mcp-server/src). Manifest ids contain a colon and MCP names do not, so no heuristic mapping between the two namespaces is made.

**undecidable reasons**

- stub_arm: a match arm exists but its body says the action is not implemented.
- label_arm: the only match arms are display labels (an arm whose body is a bare string or Some("...")).
- matches_macro: the only reference is inside matches!(...), which may be a predicate and not a handler.
- slint_dispatch: the id is compared in a .slint file (a UI-side handler), which this Rust-source rule does not count; it needs a human decision on whether the Slint handler is a feature.
- prefix_gate_unresolved: the id's prefix has a strip_prefix gate whose block could not be delimited, so name dispatch inside it cannot be ruled in or out.

**known limits**

- Arm presence proves a handler is reachable from code, not that its output is complete or correct.
- A name literal inside a prefix block is matched by comparison with the gate's binding or an arm of match on that binding; an unrelated arm with the same name inside the same block would be counted.
- Ids dispatched only through data (a table looked up at runtime) classify DECLARED.
- metadata_wired_flag is the generated tool_metadata.rs flag, recorded for cross-checking only.
