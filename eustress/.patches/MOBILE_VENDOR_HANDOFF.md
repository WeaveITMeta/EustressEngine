# Handoff: `mobile/vendor-patches`

This branch is current `main` (`f209ea80236ee205a01e6b24a10daf3dc38438d7`) plus four path patches. Nothing else. App and engine code stays on `mobile/player-parity`, which rebases onto this branch. Do not merge this branch into `main`, and do not fold Player, bridge, or gallery crates back onto it.

Drop a patch when upstream Bevy or android-activity ships the same fix. Until then `[patch.crates-io]` in `eustress/Cargo.toml` replaces the crates.io crate, and `eustress/Cargo.lock` drops that crate's registry `source` and `checksum` because a path patch has neither.

## Why stock upstream fails on Android

| Crate | Stock failure | What this patch changes | Detail |
| --- | --- | --- | --- |
| `bevy_app` 0.19.0 | `App::finish` / `SubApp::finish` capture `plugin_registry.len()` once. `RenderPlugin::build` runs before `GameActivity` `onSurfaceCreated`, so GLES has no surface and `request_adapter` fails. The Player adds `RenderPlugin` from a gate plugin's `finish` after `RawHandleWrapper` exists; those appended plugins were built and then never finished, so the device stayed in `FutureRenderResources`. | Both finish loops walk while the registry grows. Plugins added during `finish` are finished in the same pass. Desktop apps do not add plugins from `finish`, so their order is unchanged. | `.patches/bevy_app-0.19.0/PATCH.md` |
| `bevy_render` 0.19.0 | Android GLES often has no `EGL_KHR_gl_colorspace`, so `DownlevelFlags::SURFACE_VIEW_FORMATS` and `VIEW_FORMATS` are absent. Stock `create_surfaces` still requests an sRGB `view_formats` entry. `Surface::configure` fails (`SURFACE_VIEW_FORMATS are required but not supported`) and the next `Surface::get_current_texture` panics because the surface was never configured. Suspend left the old swapchain in place after the surface was dropped. | Without those flags the surface is configured with an empty `view_formats` list and the swapchain view uses the surface format. Adapters that have the flags keep the sRGB view. `SwapchainHold` makes `create_surfaces` and `prepare_windows` skip the swapchain across suspend. `create_surfaces` also logs format, view format, and size. | `.patches/bevy_render-0.19.0/PATCH.md` |
| `bevy_light` 0.19.0 | Feature unification keeps `bevy_gizmos` on through `eustress-common`. `LightPlugin` then adds `LightGizmoPlugin`, whose system requires `Assets<GizmoAsset>`. Only `GizmoPlugin` inserts that storage, and the mobile Player does not add `GizmoPlugin`, so the first frame panics. A Cargo feature on this patch would unify into Studio. | When `EUSTRESS_DISABLE_LIGHT_GIZMOS` is set, `LightPlugin` does not add `LightGizmoPlugin`. `player-mobile`'s `build_game` is the only setter. Desktop and Studio leave it unset. | `.patches/bevy_light-0.19.0/PATCH.md` |
| `android-activity` 0.6.1 | `map_input_state_to_text_event_callback` builds a slice from `GameTextInputState.text_UTF8` with `slice::from_raw_parts`. GameTextInput leaves that pointer null until the field has text. Focusing search aborted: null pointer, `src/game_activity/mod.rs`. The abort is inside the crate, before `TextInputState` is returned. | A null pointer or a length of 0 is an empty slice, decoded as `""`. Stay on 0.6.1: `games-activity` 4.4.0 matches this crate's native glue. | `.patches/android-activity-0.6.1/PATCH.md` |

## What is intentionally not here

Workspace members `crates/bridge-core`, `crates/bridge-android`, `crates/bridge-ios`, and `crates/player-ios` are app crates. They land on `mobile/player-parity`. So do `android-build`, the Slint Android backend, and every other `Cargo.lock` package added for the Player. Existing patches already on `main` (`gpu-allocator`, `fjall`, `lsm-tree`, `avian3d`, the Slint software renderer) are untouched by this commit.
