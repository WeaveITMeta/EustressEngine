# Mobile Player parity

Compared with the desktop Player (`crates/client`, `crates/play-runtime`, `crates/player-web`) and Studio's identity sign-in (`crates/engine/src/auth.rs`). Status is what this branch actually does.

| Desktop feature | Mobile status | Notes |
| --- | --- | --- |
| API base `EUSTRESS_API_URL` / `--api-url` | done | Mobile also accepts `--env production\|staging`. Compile-time default is staging (`https://api-staging.eustress.dev`). Desktop default stays production. Set before `api_base()`'s `OnceLock`. |
| Gallery browse and search | done | `GET /api/gallery?q=&limit=` and, with an empty search, `GET /api/gallery/featured`. Same JSON aliases as `crates/web/src/api/gallery.rs` (`simulations`, `author_name`, `play_count`). Slint list. |
| Identity sign-in | done | `POST /api/auth/challenge`, `POST /api/auth/verify-challenge` with `format: eustress-login-v1`, signature over `login_message`, then `GET /api/auth/me`. Token key is `login_file()` so staging and production do not share a file. |
| Token storage | partial | Android: EncryptedSharedPreferences with a Keystore `MasterKey` (`bridge-android` → `Bridge.java`). iOS: Keychain functions are stubs and return errors. Host `cargo check` uses an in-memory store. |
| Download and cache a published Space | done | `eustress_networking::published::fetch_published`, the same manifest, chunk, and `.pak` requests as `space_fetch`. Chunks land in `{files}/eustress/echk/{hash}.echk`. A legacy `.pak` unpacks under `pak/{id}`. |
| Open the Space mesh | done in code, host-tested | `eustress_networking::published::materialize_world` writes the download into `files/eustress/live/<pid>/Universe`, `space://` was registered on that folder before AssetPlugin, and `tree_read::open_player_world_dir` plus `PlayRuntimePlugin` (role Replica) draw it. Terrain, directional lights, materials, and celestials come from the shared crates. The gallery yard is removed only after that open succeeds. The gallery camera and its directional light are not yard entities, so they stay; `gate_gallery_camera` turns the gallery camera off once a play camera is active. Billboard and particle shaders register when `Assets<Shader>` exists (`cleanup` after SurfaceGate on mobile). Terrain, water, the far field, and the moon, cloud, and sky-dome materials queue until `RenderApp` exists and install from `SurfaceGate::finish`. Mobile still does not add `SharedLightingPlugin` (sky, atmosphere, moon, clouds); desktop does. parity8 opened Box Head Zombie Defense Tycoon (696 parts) and the view was the clear color: primitive parts load `parts/block.glb` and the other shapes from the default asset source, and those files were not in the APK (only character GLBs were). `copyPartGlbs` now packs them at `assets/parts/`, which is what Android's AssetManager serves for `parts/block.glb`. A play camera still sitting on the `(0, 12, 24)` fallback is moved to look at the spawn when that spawn is away from the origin; a Space camera CFrame is left alone. Opening logs the spawn, the space camera, the light count, and the part-mesh count. There is no display on this host, so the fixture test does not render a frame. `opened_fixture_space_has_a_camera_a_light_and_a_mesh` opens a Part plus a SpawnLocation and checks a `Mesh3d`, a `DirectionalLight`, an active world camera, and an avatar on the pad. Pixels of a downloaded Space are unverified until the next emulator run. |
| Join over WebTransport | done | `native::start_join` + `session::begin_join` + `NetPlugin`. `Hello` uses `wire::PROTOCOL_VERSION` (5). Same link parser: `split_link_extras` / `parse_join_link`. A published Space does not join. Desktop (`net_play::spawn_avatar_in_opened_world`) says a published world has no host, places the avatar on the Space's SpawnLocation, and writes `LocalWorldReady` that nothing reads. Mobile `begin_published` does the same and logs `published play … does not join a host`. parity8's Box Head open is that path, so the log has no Hello. A join link logs `net: joining host:port as name protocol 5` before `start_join`, the same line desktop logs. |
| Deep link `eustress-player://` | partial | Android intent-filter and `PlayerActivity.onNewIntent`. Desktop (`client/src/main.rs`) never applies `api=` from a link; it only calls `check_api` and refuses a mismatch. `--api-url` is the only thing that sets the API. Mobile does the same check and does not set the API from the link. iOS URL scheme is in `crates/player-ios/Info.plist` and is unverified (no Apple SDK). |
| `input_actions` and touch | done in code, host-tested | `eustress_common::input_actions`. Dynamic thumbstick, jump circle, right-half camera drag at 0.01 rad/logical px, pinch zoom. A finger pushed up is `+Move.y`, the same sign as W, so `camera_relative_direction` walks camera-forward. Slint is dispatched the pointer; finger ownership is one owner for the finger's life. Gallery sets `capture_all`. While playing, `capture_all` is off, so a tap on the Gallery button was `FingerOwner::World` (`kept by the world` in the parity8 resume log) and Slint never saw it. A point on a Slint `TouchArea` or `TextInput` is forwarded as well. Stick, camera, and pinch fingers are not. The ring and knob stay on screen for the whole session, at the lower-left rest point while the finger is up and under the finger while it is down. The knob is the finger offset clamped to the ring radius, and `present` asks Slint to redraw while the finger is down and for two frames after it lifts, so the knob is not left at the rim once `held=false`. `the_knob_tracks_the_finger_and_stays_inside_the_ring` and `lift_resets_the_stick` cover that. A jump tap whose press and release arrive in the same frame still sets Jump (`a_jump_tap_that_starts_and_ends_in_one_frame_still_presses`); `drive_locomotion` logs the event, a rejection, and the y change. |
| Desktop keyboard and mouse | done | WASD, Space, Shift, Ctrl, mouse-look pixels × `sensitivity` 0.003, wheel zoom. Arrow-key orbit and Escape are unchanged. |
| Follow camera | done in code, host-tested | `avatar::control::camera_follow` via `AvatarRuntimePlugin` (`AvatarHost::Client`). Same offset, eye height, smoothing, and pitch clamp (`±1.35` rad) as desktop. Once the avatar camera exists, `claim_follow_camera` makes it the active view (order 1) and turns off the Space's `ScriptedPlayCamera` and the gallery camera. A finger moving up subtracts the screen delta from pitch, matching Arrow Up: positive pitch lifts the camera. The angle clamp is still ±1.35, and `follow_camera_translation` also keeps the camera Y at least 0.35 m above the feet, because `sin(-1.35) * distance` is under the ground. If the orbit ray hits solid geometry, `pull_follow_camera` moves the camera to the near side of the hit and `camera_follow` aims at that point, so the next frame does not lerp back through the wall. `a_pitch_under_the_ground_stays_above_the_floor_and_a_hit_pulls_the_camera` covers both. A body that is asking to move and not moving is logged as blocked. `CameraType` Scriptable still writes the script CFrame onto that same camera and follow stands down, which is the desktop rule. A Space camera at `(0, 20, 20)` with type Custom does not stay the view. |
| Character avatar | done in code, host-tested | `SpawnAvatar` with the default descriptor (Male → `bundled://characters/y_bot.glb`, plus the male idle/walk/run/jump clips) at the Space's SpawnLocation for a published play, which is where desktop puts it. Android's `copyCharacterGlbs` packs every `assets/characters/**/*.glb` (y_bot, x_bot, voltec_supreme, and their animations). `Bridge.installBundledAssets` copies them to `filesDir/bundled` and `EUSTRESS_BUNDLED_ASSETS` is the first `bundled://` candidate. On Android that source is a `ContainedFileReader` on the absolute files folder: `platform_default` would ask the APK AssetManager and return `NotFound("characters/y_bot.glb")` even when `files/bundled/characters/y_bot.glb` exists. The mesh count is logged the frame the avatar exists and again when the load finishes or fails, not after 180 frames. `bundled_reader_reads_the_character_from_an_absolute_folder` reads that relative path back. `gltf_animation` is on so those clips parse. The spawn logs the body URL, the resolved file, and whether that file exists. The mesh count waits until `AwaitingRigBind` drops, which is after the scene's descendants spawn; `Loaded` on the root used to log `meshes=0` and scale 0 while the body was already on screen. It then logs the mesh count, the mesh world position and scale, and how many of those meshes are skinned. The spawn goes through `SpaceCharacterPolicy::apply`, the same dress as desktop, so StarterPlayer jump height and jump power apply. Desktop gravity is `9.80665` m/s² (`GRAVITY_MPS2` / `STANDARD_GRAVITY`). Desktop jump height is `jump_apex_m` (default `0.55 + 0.35 * stride_scale` metres, about 0.886 m on the default body) and the take-off is `sqrt(2·g·apex)` (about 4.168 m/s) unless the Space sets `CharacterJumpPower`. Skinned body meshes get `NoFrustumCulling` so a bind-pose box cannot hide them. The fixture host test requires at least one mesh under the avatar, the follow camera aimed at that avatar, a stick-forward displacement along camera-forward, and a jump that raises y. iOS has no copy path. `view-look` (TonyMcMapface / SMAA) is off; the camera falls back to Reinhard. |
| Safe area | partial | `SafeArea` trait. Android reads system bars and cutout, divided by density. iOS UIKit call is written and unverified. |
| Haptics | partial | `Haptics` trait. Android `performHapticFeedback` plus `VibrationEffect` for a custom pulse. iOS feedback generators are written and unverified. Jump triggers `ImpactMedium`. |
| Suspend / resume | done | `SurfaceGate` still waits for `onSurfaceCreated`. Suspend sets `SwapchainHold` and drops the overlay texture slot. The Skia renderer is not cleared. Resume logs every directional light's illuminance and shadow flag, `GlobalAmbientLight`, `LightUnits` ev100, and the active camera's exposure and tonemapper, and the surface format. An ambient brightness that came back as 0 is restored to 280. A physical size that is only the last size with the axes swapped (1080×2400 right after 2400×1080) is kept until it has been the window for 400 ms, so a resume configuration change does not turn the landscape panel portrait. `a_swapped_resume_size_is_kept_until_it_holds` covers that. |
| Android Vulkan debug flags | done in code | Debug APKs set `debug_assertions`, so `InstanceFlags::from_build_config` is `DEBUG \| VALIDATION \| VALIDATION_INDIRECT_CALL`. `Device::new` then builds the indirect-validation bind-group layout and names it. The API 36 ranchu driver (`-gpu host`) SIGSEGVs in `vkSetDebugUtilsObjectNameEXT` on that call. Phase 0 APKs were release-profile native code, where Bevy strips `VALIDATION_INDIRECT_CALL` and `DEBUG` is off, and that emulator did not crash. Device creation is otherwise the same. On Android, `android_instance_flags` removes `DEBUG`, `VALIDATION`, `VALIDATION_INDIRECT_CALL`, and `GPU_BASED_VALIDATION` after `with_env()`, so `WGPU_DEBUG` cannot turn them back on. Vulkan stays the backend. parity5 created the device: `InstanceFlags(0x0)`, Vulkan NVIDIA GeForce RTX 2080 Ti, no driver crash. The first frame then panicked on `BillboardAtlas`. Pixels are still unverified. |
| Android app classes from native | confirmed on emulator | `android_main` is a native thread. `FindClass` there uses the system class loader (`DexPathList[[directory "."]]`), so `dev.eustress.player.Bridge` in the app dex threw `ClassNotFoundException` and the next `FindClass` aborted. App classes go through the application `ClassLoader.loadClass` and are cached as a global ref. A failed JNI call clears the pending exception before the next call. `files_dir` is `Context.getFilesDir()` and does not look up `Bridge`. `player-mobile` has no JNI of its own. The parity3 retest got past this: the abort moved to the Activity argument check below. |
| Activity versus Application | confirmed on emulator | parity4: the self-check logged `activity=dev.eustress.player.PlayerActivity`, every Bridge signature resolved, `filesDir`, `intentUri`, `insets`, and a `secureGet` probe, then `installBundledAssets` returned `files/bundled`. The process then panicked in `BillboardPipelinePlugin::build` before any adapter. |
| Deferred RenderApp | done in code, host-tested | parity4 panicked at `billboard_pipeline.rs` `resource_mut::<Assets<Shader>>()` before any adapter. `RenderPlugin` inserts that storage, and SurfaceGate adds `RenderPlugin` only after the window handle exists. Billboard and particle shaders now register when the storage exists (desktop `build`, mobile `cleanup`). Terrain surface, water, and far field, plus moon, clouds, and sky dome, queue their `MaterialPlugin`s and `SurfaceGate` drains the queue after `RenderPlugin`. Terrain texture arrays are not marked unavailable merely because RenderApp is missing during `finish`. Systems that require mesh, image, or standard-material storage wait until those resources exist, so an update before the renderer does not panic. `GizmoPlugin` is disabled (it arrives only because `eustress-common` enables `bevy_gizmos`). `audio-all-formats` matches the desktop Player so `Assets<AudioSource>` exists. Bevy's `debug` feature is on so a missing resource names its type. Android disables `LogPlugin` because `android_logger` already set the global logger (parity4 logged that error). Host test `mobile_app_updates_without_a_window_while_render_is_deferred` builds this app without `WinitPlugin`, calls `finish` and `cleanup` (headless `SurfaceGate` does not create a device), and runs three updates. parity5 got past shader registration and created the Vulkan device, then died on the next row. |
| Billboard atlas thread | confirmed on emulator | parity5 panicked on the first frame: `NonSend` `BillboardAtlas` was inserted on the schedule thread and `atlas_ready` read it on a pool thread (`non_send.rs`). The atlas holds a `Handle`, byte buffer, and slot map. The `Pixmap` is local to the raster system, so the atlas is a normal `Resource`. `BillboardTextState` (`FontSystem`, `SwashCache`) stays `NonSend` and is inserted from a Startup system on the thread that calls `App::update`, not from `Plugin::build`. Slint's `SlintContext` and `ShellUi` were already inserted from the `init_slint` exclusive system on that same thread. `bevy_audio` and the mobile plugin set do not insert any other `NonSend` during `build` or `finish`. The desktop client crate is not in this app. `App` is `!Send`, so the host test cannot move it. Both host tests call `finish` and `cleanup` the way Android does before the first frame. Headless `SurfaceGate` does not create a device. `frame_schedule_reads_the_billboard_atlas_from_a_pool_thread` checks font state is absent after `build`, registers `Assets<Image>`, and runs startup plus three updates. The compute pool is the other thread and evaluates `atlas_ready`. parity6 confirmed this: the Vulkan device came up, the overlay was scheduled, and the process did not abort on the atlas. The next panic is the row below. |
| Light gizmos and system errors | confirmed on emulator | parity6 panicked in `bevy_gizmos::update_gizmo_meshes<bevy_light::gizmos::LightGizmoConfigGroup>`: `ResMut<Assets<GizmoAsset>>` failed validation. `GizmoPlugin` was already disabled. `LightPlugin` still adds `LightGizmoPlugin` while `bevy_gizmos` is on, and only `GizmoPlugin` inserts that asset storage. The patched `bevy_light` skips `LightGizmoPlugin` when `EUSTRESS_DISABLE_LIGHT_GIZMOS` is set. `build_game` sets it, so those systems are not scheduled. The host sweep `every_scheduled_system_passes_param_validation` adds the same Image, Mesh, Camera, and Light plugins `SurfaceGate` adds (not `RenderPlugin`, which needs a display, and not the pipeline plugins whose `build` requires `RenderApp`), calls `finish` and `cleanup`, runs Startup, one fixed step, and two more updates, and records every system whose params fail validation. That sweep flagged one system, `update_gizmo_meshes<LightGizmoConfigGroup>`, which is the plugin this removes. On Android, `App::set_error_handler(bevy::ecs::error::warn)` logs a missing-resource validation and skips that system. A `panic!` in a system body still aborts. parity7 launched with no panic and no skipped systems. |
| Gallery input and first-frame scale | confirmed on emulator | parity7 drew the staging gallery and then ignored taps and keys. Bevy 0.19 touch positions are already logical, and `pointer_input` divided by the scale factor again, so hits missed every widget. Keys reached GameActivity's `InputConnection` and were not dispatched to Slint, and `request_redraw` was empty, so the overlay logged a single draw. A focused Slint `TextInput` calls `GameActivity_showSoftInput` / `hideSoftInput` (and sets the Bevy window's `ime_enabled`, which winit mirrors). `request_redraw` sets a dirty flag and `render_slint` calls `render_to_texture` when that flag or an animation is set, logging every draw. The first overlay was 3360×1890 because Bevy multiplies the default 1280×720 by density (420/160) before the native 2400×1080 size is on the component, and `init_slint` then resized at scale 1. The overlay now uses the winit window's native size and the window scale factor on the first Slint frame. `pointer_on_sign_in_fires_the_callback_and_redraws` presses and releases the Sign in button through the software renderer, and checks the playing Gallery button is a TouchArea. parity8 confirmed taps, the first-frame scale, a redraw every frame, and that tapping the staging Space downloads and opens it. |
| Soft keyboard | done in code | parity8 aborted in `android-activity` 0.6.1 `game_activity/mod.rs` `from_raw_parts` the frame search focused (`ime_enabled=true`). GameTextInput's `text_UTF8` is null until the field has text. The patched crate treats a null pointer or a length of 0 as an empty string. The same frame's first `EditorInfo` was `inputType=NULL`, so the IME did not show a keyboard (`mInputShown` stayed false); a later one was `TYPE_CLASS_TEXT` with action Done, after the process had already aborted. `show_soft_keyboard` now calls `set_ime_editor_info(TYPE_CLASS_TEXT, Done)` and `set_text_input_state` before `show_soft_input(SHOW_IMPLICIT)`. `GameActivity_showSoftInput` already posts that show onto the UI thread. Not yet re-run on the emulator. |
| Debug signing | done | `crates/player-android/debug.keystore` (alias `androiddebugkey`, store and key password `android`) is the debug signing config. It is not a release key. An APK signed with a machine-local debug key still has to be uninstalled once before this key will install over it. |
| Luau `InputContext` scripting | not done | The action layer is the Rust contexts from the input design (CoreCharacter, CoreCamera, World, TextFocus, SystemMenu). Script-defined contexts are not loaded. |
| iOS app compile | unverified | `crates/player-ios` and `crates/bridge-ios` host-check. No `xcrun` on this machine. Keychain is an explicit stub. |
