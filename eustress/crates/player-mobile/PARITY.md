# Mobile Player parity

Compared with the desktop Player (`crates/client`, `crates/play-runtime`, `crates/player-web`) and Studio's identity sign-in (`crates/engine/src/auth.rs`). Status is what this branch actually does.

| Desktop feature | Mobile status | Notes |
| --- | --- | --- |
| API base `EUSTRESS_API_URL` / `--api-url` | done | Mobile also accepts `--env production\|staging`. Compile-time default is staging (`https://api-staging.eustress.dev`). Desktop default stays production. Set before `api_base()`'s `OnceLock`. |
| Gallery browse and search | done | `GET /api/gallery?q=&limit=` and, with an empty search, `GET /api/gallery/featured`. Same JSON aliases as `crates/web/src/api/gallery.rs` (`simulations`, `author_name`, `play_count`). Slint list. |
| Identity sign-in | done | `POST /api/auth/challenge`, `POST /api/auth/verify-challenge` with `format: eustress-login-v1`, signature over `login_message`, then `GET /api/auth/me`. Token key is `login_file()` so staging and production do not share a file. |
| Token storage | partial | Android: EncryptedSharedPreferences with a Keystore `MasterKey` (`bridge-android` → `Bridge.java`). iOS: Keychain functions are stubs and return errors. Host `cargo check` uses an in-memory store. |
| Download and cache a published Space | done | `eustress_networking::published::fetch_published`, the same manifest, chunk, and `.pak` requests as `space_fetch`. Chunks land in `{files}/eustress/echk/{hash}.echk`. A legacy `.pak` unpacks under `pak/{id}`. |
| Open the Space mesh | done in code | `eustress_networking::published::materialize_world` writes the download into `files/eustress/live/<pid>/Universe`, `space://` was registered on that folder before AssetPlugin, and `tree_read::open_player_world_dir` plus `PlayRuntimePlugin` (role Replica) draw it. Terrain, directional lights, materials, and celestials come from the shared crates. The gallery yard is removed only after that open succeeds. Billboard and particle render setup waits until `SurfaceGate` has created RenderApp (their `cleanup`, which runs after `finish`). Pixels on a device are unverified. |
| Join over WebTransport | done | `native::start_join` + `session::begin_join` + `NetPlugin`. `Hello` uses `wire::PROTOCOL_VERSION` (5). Same link parser: `split_link_extras` / `parse_join_link`. |
| Deep link `eustress-player://` | partial | Android intent-filter and `PlayerActivity.onNewIntent`. Desktop (`client/src/main.rs`) never applies `api=` from a link; it only calls `check_api` and refuses a mismatch. `--api-url` is the only thing that sets the API. Mobile does the same check and does not set the API from the link. iOS URL scheme is in `crates/player-ios/Info.plist` and is unverified (no Apple SDK). |
| `input_actions` and touch | done | `eustress_common::input_actions`. Dynamic thumbstick, jump circle, right-half camera drag at 0.01 rad/logical px, pinch zoom. Slint is dispatched the pointer; finger ownership is one owner for the finger's life. Gallery sets `capture_all`. |
| Desktop keyboard and mouse | done | WASD, Space, Shift, Ctrl, mouse-look pixels × `sensitivity` 0.003, wheel zoom. Arrow-key orbit and Escape are unchanged. |
| Follow camera | done | `avatar::control::camera_follow` via `AvatarRuntimePlugin` (`AvatarHost::Client`). Same offset, eye height, and smoothing as desktop. |
| Character avatar | partial | `SpawnAvatar` with the default descriptor (Male → `characters/y_bot.glb`, plus the male idle/walk/run/jump clips). Android's `copyCharacterGlbs` packs every `assets/characters/**/*.glb` (y_bot, x_bot, voltec_supreme, and their animations). `Bridge.installBundledAssets` copies them to `filesDir/bundled` and `EUSTRESS_BUNDLED_ASSETS` is the first `bundled://` candidate. `gltf_animation` is on so those clips parse. Whether the mesh loads on a device is unverified. iOS has no copy path. `view-look` (TonyMcMapface / SMAA) is off; the camera falls back to Reinhard. |
| Safe area | partial | `SafeArea` trait. Android reads system bars and cutout, divided by density. iOS UIKit call is written and unverified. |
| Haptics | partial | `Haptics` trait. Android `performHapticFeedback` plus `VibrationEffect` for a custom pulse. iOS feedback generators are written and unverified. Jump triggers `ImpactMedium`. |
| Suspend / resume | done | `SurfaceGate` still waits for `onSurfaceCreated`. Suspend sets `SwapchainHold` and drops the overlay texture slot. The Skia renderer is not cleared. |
| Android Vulkan debug flags | done in code | Debug APKs set `debug_assertions`, so `InstanceFlags::from_build_config` is `DEBUG \| VALIDATION \| VALIDATION_INDIRECT_CALL`. `Device::new` then builds the indirect-validation bind-group layout and names it. The API 36 ranchu driver (`-gpu host`) SIGSEGVs in `vkSetDebugUtilsObjectNameEXT` on that call. Phase 0 APKs were release-profile native code, where Bevy strips `VALIDATION_INDIRECT_CALL` and `DEBUG` is off, and that emulator did not crash. Device creation is otherwise the same. On Android, `android_instance_flags` removes `DEBUG`, `VALIDATION`, `VALIDATION_INDIRECT_CALL`, and `GPU_BASED_VALIDATION` after `with_env()`, so `WGPU_DEBUG` cannot turn them back on. Vulkan stays the backend. The parity3 emulator retest still died in JNI (`installBundledAssets`) before the device was created, so this is still unverified. |
| Android app classes from native | confirmed on emulator | `android_main` is a native thread. `FindClass` there uses the system class loader (`DexPathList[[directory "."]]`), so `dev.eustress.player.Bridge` in the app dex threw `ClassNotFoundException` and the next `FindClass` aborted. App classes go through the application `ClassLoader.loadClass` and are cached as a global ref. A failed JNI call clears the pending exception before the next call. `files_dir` is `Context.getFilesDir()` and does not look up `Bridge`. `player-mobile` has no JNI of its own. The parity3 retest got past this: the abort moved to the Activity argument check below. |
| Activity versus Application | done in code | `ndk_context`'s context is the `Application` (`android-activity` stores the app global). parity3 aborted in CheckJNI: that object was argument 1 of `Bridge.installBundledAssets(Activity)`. The abort is not a Rust error. Activity parameters (`insets`, `haptic`, `intentUri`) now receive `AndroidApp::activity_as_ptr()`. Methods that only need a `Context` (`installBundledAssets`, `filesDir`, `secureGet`, `secureSet`, `secureRemove`, `hapticCustom`) take `android.content.Context`. Before each static call, `IsInstanceOf` checks the argument and a mismatch is logged instead of calling. Startup logs every Bridge signature and the safe call results (haptics are not played; the keystore is not written). Calls run on the attached native thread, not the Java UI thread. Emulator re-run of this build is unverified from this machine. |
| Debug signing | done | `crates/player-android/debug.keystore` (alias `androiddebugkey`, store and key password `android`) is the debug signing config. It is not a release key. An APK signed with a machine-local debug key still has to be uninstalled once before this key will install over it. |
| Luau `InputContext` scripting | not done | The action layer is the Rust contexts from the input design (CoreCharacter, CoreCamera, World, TextFocus, SystemMenu). Script-defined contexts are not loaded. |
| iOS app compile | unverified | `crates/player-ios` and `crates/bridge-ios` host-check. No `xcrun` on this machine. Keychain is an explicit stub. |

No store listing, no release, and this branch does not target `main`.
